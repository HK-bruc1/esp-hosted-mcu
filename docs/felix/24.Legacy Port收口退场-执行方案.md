# 24. Legacy Port 收口退场——执行方案

> 基线：2026-06-08，基于 23 号文档 WP 0-6 执行结果。
> 本文档是 23 号文档 WP 4（Legacy ESP/Freertos port adapter 退场）的深化执行方案。
> 目标：`host/port/esp/freertos/` 不再编译进 ESP-IDF host build。

---

## 1. 动机

23 号文档完成后，consumer 侧 legacy vtable 依赖已清零，但 active source set 中仍同时编译两套 port 层：

```text
New port (host/port/esp-idf/)          Legacy port (host/port/esp/freertos/)
├── h_transport_spi.c ──extern──→      ├── port_esp_hosted_host_spi.c
├── h_osal.c (真实 ESP-IDF adapter)     ├── port_esp_hosted_host_os.c (定义 g_h)
├── h_event.c                          ├── port_esp_hosted_host_transport_defaults.c
├── h_wifi_type_adapt.c                └── per-transport bus helper
└── h_control_serial_adapter.c
```

遗留问题：
- `g_h` 仍在 active source set 中定义（`port_esp_hosted_host_os.c`）
- `h_transport_spi.c` 等新 adapter 通过裸 `extern` 调用 `hosted_spi_init()` / `esp_hosted_tx()`，是隐式链接时绑定
- GPIO/default config helper 散落在 legacy port 文件中
- 新平台移植者会看到两套 port 模式

---

## 2. 目标

`host/port/esp/freertos/src/*.c` 和 `host/port/esp/freertos/include` 从 ESP-IDF host active source set 完全移除。

完成后允许声明：

> 当前 ESP32 / ESP-IDF host active source set 仅编译 `host/port/esp-idf/` 一套 port 层；不再依赖 `g_h` 旧 vtable 定义；`esp_hosted_tx()` / `check_if_max_freq_used()` 从隐式 extern 收口到内部驱动 API header。

禁止声明：
- "Host 通用框架 v1 已完成"
- "第二平台移植充分性已经证明"

---

## 3. 完成强度定位

沿用 23 号文档的分级体系：

| 等级 | 名称 | 本次变更 |
|---|---|---|
| L0 | Core closure | 不变（12/12） |
| L1 | Wi-Fi 主链路 closure | 不变 |
| L2 | ESP32 active source closure | **本次推进**：legacy port 退场 |
| L3 | 移植友好型 closure | 本次完成后结构就绪，待第二平台验证 |

### 4.4 `esp_hosted_tx()` 收口

不改变运行时链路，只将隐式变显式：

```text
Before:
  h_transport_spi.c — extern esp_hosted_tx(...) —→ spi_drv.c
  h_transport_spi.c — extern hosted_spi_init(...) —→ port_esp_hosted_host_spi.c

After:
  h_transport_spi.c — #include "transport_drv_api.h" —→ spi_drv.c
  h_transport_spi.c — #include "h_transport_spi_bus.h" —→ h_transport_spi_bus.c
```

`transport_drv_api.h` 声明的符号：

```c
/* Transport leaf driver internal API — not a porting contract.
 * Each leaf driver (spi / sdio / spi_hd / uart) must provide
 * these two symbols. */
int  esp_hosted_tx(uint8_t iface_type, uint8_t iface_num,
                   uint8_t *payload_buf, uint16_t payload_len,
                   uint8_t buff_zerocopy, uint8_t *buffer_to_free,
                   void (*free_buf_func)(void *ptr), uint8_t flags);
void check_if_max_freq_used(uint8_t chip_type);
```

`check_if_max_freq_used()` 当前已在 `host/core/include/h_internal/h_transport_drv.h:159` 声明，本次将其声明迁移到 `transport_drv_api.h`，`h_transport_drv.h` 改为 include 该头。各 leaf driver 中的定义保留不变。

## 6. 工作包

### Staging 策略：避免重复符号

WP2–WP4 将 legacy 函数迁入新文件时，旧文件仍在 CMake active source set。按迁移类型采用两种策略：

| 迁移类型 | 策略 | 原因 | 示例 |
|---|---|---|---|
| GPIO helper（WP2） | **新命名** | 调用方可控（仅 4 个 `h_transport_*.c`），改名不会破坏外部 API | `hosted_config_gpio()` → `h_gpio_config()` |
| Default config（WP3a） | **原子替换** | 函数名是 public API，不能改名；新旧文件不能同时编译 | `esp_hosted_get_default_spi_config()` 保持原名；同一 commit 完成 CMake 替换 |
| Bus helper（WP4） | **新命名** | 调用方可控（仅 4 个 `h_transport_*.c`），改名不会破坏外部 API | `hosted_spi_init()` → `h_spi_bus_init()` |
| Header-only config（WP3b/3c） | **直接迁入 `h_port_config.h`** | 宏通过 `#include` 可见，无链接期符号冲突 | Wi-Fi / BT feature flag 宏 |

旧函数在旧文件中变为死代码，WP 6 统一从 CMake 移除旧文件。

### WP 3a：Default transport config 迁移（原子步骤）

**目标：** `esp_hosted_get_default_*_config()` 从 `port_esp_hosted_host_transport_defaults.c` 迁入 `h_transport_defaults.c`。

**Staging 策略：** 函数名是 public API，**不能改名**。因此 `h_transport_defaults.c` 加入 CMake 和旧文件 `port_esp_hosted_host_transport_defaults.c` 从 CMake 移除**必须在同一个 commit 内完成**，否则会出现重复符号。

**动作：**

1. 迁移 4 个函数到 `h_transport_defaults.c`（保持原名）：
   - `esp_hosted_get_default_sdio_config()`
   - `esp_hosted_get_default_spi_config()`
   - `esp_hosted_get_default_uart_config()`
   - `esp_hosted_get_default_spi_hd_config()`
2. 所需 `H_*` 常量已由 `h_port_config.h` 提供；内部 `#ifdef` 改为 `#if`
3. **同一 commit 内**：
   - CMakeLists `srcs` 新增 `h_transport_defaults.c`
   - CMakeLists `srcs` 删除 `port_esp_hosted_host_transport_defaults.c`
4. 调用方无需修改（函数签名和名称不变）

**验收：** 四 transport 编译通过；CMakeLists 中 `port_esp_hosted_host_transport_defaults.c` 已移除；无链接期重复符号错误。

### WP 4：Per-transport bus helper 迁移

**目标：** 将 `hosted_spi_init/reconfig/deinit` 等 bus helper 从 legacy per-transport port 文件以**新函数名**迁入对应的 `h_transport_*_bus.c`，避免与仍在 CMake 的旧文件产生重复符号。

**Staging 策略：** 使用新命名。旧函数保留在 legacy per-transport 文件（变为死代码，WP 6 随 CMake 移除一并删除）。调用方 `h_transport_*.c` 同步更新。

**动作（以 SPI 为例，其他 transport 同理）：**

1. 在 `h_transport_spi_bus.c` 中实现以下函数（新命名），内部 OSAL 调用走 `h_*` wrapper：

   | 旧函数（legacy） | 新函数（`h_transport_spi_bus.c`） |
   |---|---|
   | `hosted_spi_init()` | `h_spi_bus_init()` |
   | `hosted_spi_reconfig()` | `h_spi_bus_reconfig()` |
   | `hosted_spi_deinit()` | `h_spi_bus_deinit()` |

   同理：
   - SPI-HD：`hosted_spi_hd_*` → `h_spi_hd_bus_*`
   - SDIO：`hosted_sdio_*` → `h_sdio_bus_*`
   - UART：`hosted_uart_*` → `h_uart_bus_*`

2. 新增 `h_transport_spi_bus.h`（依此类推）声明这些新函数
3. **允许保留 ESP-IDF bus driver 头文件**（`driver/spi_master.h` 等）——bus 层原生依赖
4. **允许使用 ESP-IDF driver API 原生句柄**（`spi_device_handle_t`、`sdmmc_card_t` 等）
5. 更新 `host/port/esp-idf/h_transport_spi.c`：
   - 删除 `extern hosted_spi_init()` 等声明 → `#include "h_transport_spi_bus.h"`
   - 删除 `extern esp_hosted_tx()` → `#include "transport_drv_api.h"`
   - 调用点改为新函数名（`h_spi_bus_init()` 等）
6. 旧 `hosted_spi_init()` 等定义暂时保留在 `port_esp_hosted_host_spi.c`（WP 6 随 CMake 移除删除）

**例外规则：**

ESP-IDF port 的 `h_transport_*_bus.c` 文件：
- OSAL 类（malloc/free/mutex/semaphore/sleep/timer）：**必须**走 `h_*` wrapper
- Bus 原生 API（`spi_bus_add_device`、`sdmmc_card_init` 等）：直接使用 ESP-IDF API
- 极底层 ISR/DMA/driver install 调用：按 ESP-IDF API 原样使用

**验收：** 四 transport 编译通过；`h_transport_*.c` 中无 `extern hosted_*` 声明；`h_transport_*_bus.c` 内部 `g_h.funcs`/`HOSTED_*` 调用为 0。
