# 22.当前平台完全解耦执行方案

> 本文档用于承接当前新的推进决策：**第二平台真实 PoC 暂缓，先把当前 ESP-IDF 平台 active path 做到完全解耦**。
>
> 这里的“完全解耦”不是宣称 Host 通用框架已经进入 v1，也不是替代 20 号文档的第二平台验证；它只定义当前 ESP-IDF 平台内，core、控制面、transport active path 和验证脚本应该如何继续收口。

---

## 1. 背景与结论

截至当前代码状态，Host 通用框架已经完成了核心层大部分收口：

- `host/core/src/` 12/12 文件已纳入 core isolation 口径
- Linux mock 已覆盖 12/12 core 文件生产路径，文档记录为 28/28 测试通过
- `h_wifi_types.h` 已不再通过 `ESP_PLATFORM` 直通 ESP-IDF native 类型
- `h_transport_drv.c` 已主要通过 `h_transport` / `h_osal` contract 完成总线 ready、transmit、功耗恢复等编排
- SPI 与 SPI-HD 驱动层已完成大量 legacy `_h_*` 调用迁移

但当前仍不能把项目级状态称为 v1，因为 9 号文档定义的 v1 / Milestone D 依赖第二平台真实硬件 PoC。既然第二平台 PoC 暂缓，本阶段目标应调整为：

> 在不启动第二平台 PoC 的前提下，先把当前 ESP-IDF 平台的 active path 做到完全解耦，使当前平台不再依赖 legacy vtable、legacy pserial 或未声明的旧路径存活。

## 3. 本文档目标与非目标

### 3.1 目标

本阶段目标是完成 **ESP-IDF current-platform active path full decoupling**：

1. `host/core/src/` 保持 12/12 isolation 和 12/12 mock 覆盖口径。
2. 当前 ESP-IDF 平台 active path 不再依赖 `g_h.funcs->_h_*` legacy vtable。
3. 控制面不再依赖 legacy `transport_pserial_*` 或等价旧 serial/RPC 支撑链作为不可替代前提。
4. SPI、SPI-HD、SDIO、UART 四类 ESP-IDF transport 的 active driver path 全部通过 `h_wrapper.h` / `h_port_contract.h` 入口表达平台能力。
5. CMake active source 集合中，新旧 port 层职责清晰；旧文件可保留，但不能是当前 active path 的未声明硬依赖。
6. 新增脚本化验证，覆盖 core 之外的当前平台 driver / port active path。

### 3.2 非目标

本阶段不做以下事情：

1. 不启动第二平台真实硬件 PoC。
2. 不宣称 Host 通用框架已经进入 v1。
3. 不删除所有 legacy 文件。
4. 不改变 wire protocol、RPC ID、protobuf schema 或 slave 侧行为。
5. 不把 Bluetooth、OTA、Network Split 纳入本阶段。
6. 不为了“代码看起来干净”重写 transport 生命周期；`h_transport_drv.c` 仍保留当前编排职责，除非验证证明必须拆分。

## 4. 术语定义

| 术语 | 定义 |
|---|---|
| active path | 当前 ESP-IDF 构建在某个 transport 配置下实际编译、链接并参与运行的 host/core、host/drivers、host/port 文件集合 |
| current-platform full decoupling | ESP-IDF 当前平台 active path 不再依赖 legacy vtable / legacy pserial / 未声明旧入口；所有平台能力都通过明确 contract 或 wrapper 表达 |
| legacy 文件 | 旧目录或旧实现文件；允许保留，但必须么不在 active path，要么被明确标为 adapter 边界 |
| adapter 边界 | 允许接触 ESP-IDF native API 或历史实现的最外层 port 文件，例如 `host/port/esp-idf/*` 或暂定的兼容 adapter |
| 阻塞项 | 当前缺少 contract、接口或验证方式，不能靠局部替换安全完成的项 |

## 5. 当前代码基线（执行前基线，2026-06-04 执行后见 §13 实施结果）

### 5.1 已确认的正向基线

当前代码已经具备以下基础：

- `host/core/src/h_transport_drv.c` 中未发现 `g_h.funcs`、`->_h_`、`transport_pserial_` 直接匹配。
- `host/core/src/h_serial_if.c` 中未发现 `transport_pserial_` 直接匹配。
- `host/drivers/transport/spi/spi_drv.c` 中未发现 `g_h.funcs`、`->_h_`、`transport_pserial_` 直接匹配。
- `host/drivers/transport/spi_hd/spi_hd_drv.c` 中未发现 `g_h.funcs`、`->_h_`、`transport_pserial_` 直接匹配。

### 5.2 仍存在的主要缺口

当前缺口集中在以下区域：

| 区域 | 当前事实 | 含义 |
|---|---|---|
| 控制面底层 | 当前 CMake active path 编入 `h_rpc_slave_if.c` + `serial_ll_if.c`；`serial_drv.c` 文件存在，但当前不在 CMake active source set | 控制面分析必须以 active source set 为准，不能把 inactive `serial_drv.c` 当作当前主路径 |
| `h_rpc_slave_if.c` | 直接 `#include "serial_ll_if.h"`，并通过 `serial_ll_if_g->fops->open/read/write/close` 操作底层通道 | core isolation 当前未覆盖该头文件依赖；WP 1 不能只改 `h_serial_if.c` |
| `serial_ll_if.c` | 仍使用 `g_h.funcs->_h_*`、`ESP_LOG*`，并直接调用 `esp_hosted_tx()` | 可作为 control adapter 保留，但必须明确边界；若要更强闭合，应改为 `h_*` wrapper / `h_transmit` |
| `h_rpc_core.c` | RX/TX 线程仍有 `serial_drv_open(SERIAL_IF_FILE)` 有效性检查 | 控制面入口尚未完全统一到 `h_serial_if_*` / 新 contract |
| SDIO driver | `host/drivers/transport/sdio/sdio_drv.c` 仍大量使用 `g_h.funcs->_h_*` | SDIO active path 未完成当前平台解耦 |
| UART driver | `host/drivers/transport/uart/uart_drv.c` 仍大量使用 `g_h.funcs->_h_*` | UART active path 未完成当前平台解耦 |
| wrapper / contract 校验 | `h_wrapper.h` 缺少部分 SDIO / UART wrapper；`h_validate_contracts()` 对 SDIO / UART 只做最小槽位校验 | WP 2 / WP 3 不能视为纯机械替换，需先补齐前置槽位和 fail-fast |
| CMake active set | `CMakeLists.txt` 同时加入旧 transport driver、旧 `host/port/esp/freertos` 文件和新 `host/port/esp-idf` 文件 | 需要明确哪些是 active implementation，哪些只是 adapter 或 legacy 支撑 |
| 验证脚本 | `check_core_isolation.sh` 只覆盖 core；`run_linux_mock_tests.sh` 不覆盖真实 ESP-IDF driver active path | 缺少 current-platform 解耦验收脚本 |

### 5.3 代码级前置阻塞项

以下阻塞项必须在 WP 1 / WP 2 / WP 3 大规模迁移前关闭，或在 WP 0 的 active path 矩阵中明确降级为未完成项。否则会出现“替换到一半才发现 wrapper / contract / source boundary 不成立”的返工。

| 阻塞项 | 当前代码事实 | 前置动作 | 影响范围 |
|---|---|---|---|
| SDIO / UART wrapper 缺失 | `h_transport_contract_t` 已有 `sdio_card_init`、`sdio_read_reg`、`sdio_write_reg`、`uart_flush` 槽位；`h_wrapper.h` 尚未提供对应宏 | 先补 `h_sdio_card_init`、`h_sdio_read_reg`、`h_sdio_write_reg`、`h_uart_flush` wrapper | WP 2 / WP 3 |
| SDIO `card_deinit` 语义未收口 | 旧 driver 显式调用 `_h_sdio_card_deinit`；该函数会释放 `sdmmc_card_init()` 分配的 DMA aligned buffer；新 contract 目前只有 transport `deinit` | 默认优先把 `hosted_sdio_card_deinit()` 收进 ESP-IDF SDIO adapter 的 `h_sdio_deinit_adapter()`，再调用 `hosted_sdio_deinit()`；只有验证证明 driver 必须显式分阶段 deinit 时，才新增 `sdio_card_deinit` contract 槽位 | WP 2 |
| `h_rpc_slave_if.c` 隐藏 legacy 链 | 该 core 文件直接 include `serial_ll_if.h` 并操作 `serial_ll_if_g->fops`；当前 core isolation 未检查该头文件 | 将 serial / rpc platform 低层实现移到 control adapter 边界，或重构为 `h_control_contract_t` 的 ESP-IDF port implementation；core 不允许直接依赖 `serial_ll_if.h` | WP 1 |
| `h_validate_contracts()` 不完整 | SDIO 仅校验 `sdio_read_block`；UART 仅校验 `uart_read` | 同步补齐 transport 专属必需槽位校验：SDIO 至少覆盖 `sdio_card_init`、`sdio_read_reg`、`sdio_write_reg`、`sdio_read_block`、`sdio_write_block`、`sdio_wait_intr`、reset GPIO；UART 至少覆盖 `uart_read`、`uart_write`、`uart_flush`、reset GPIO | WP 2 / WP 3 |
| thread lifecycle 映射不能逐字替换 | 旧 `_h_thread_create` 返回包装指针，`_h_thread_cancel` 会 `vTaskDelete(*thread_hdl)` 并释放包装对象；新 `h_thread_create` 通过 out 参数返回 `h_thread_t`，`h_thread_delete` 只删除任务句柄 | SDIO / UART 线程变量统一按 `h_thread_t` 使用；创建改为 `if (h_thread_create(...) != H_OK)`；删除只调用 `h_thread_delete(thread)` 并置 NULL，不再假设有额外包装对象需要释放 | WP 2 / WP 3 |

补齐后，WP 2 / WP 3 的大部分 `_h_*` 替换才可以按机械迁移处理；WP 1 才能真正声明控制面旧链路从 core 退出。

### 5.4 控制面闭合强度分级

控制面有两种可执行闭合路径，执行前必须在 WP 0 记录选择。两条路径都可以服务“当前 ESP-IDF 平台 active path 解耦”，但对后续可声明的完成强度不同。

| 路径 | 做法 | 允许声明 | 不允许声明 |
|---|---|---|---|
| A. 严格 contract closure | 新增独立 `h_control_contract_t`；`h_serial_if.c` 只通过 `h_control_*` 调用控制面字节流；ESP-IDF / Linux mock 分别实现 control contract；`h_validate_contracts()` fail-fast 校验 control 槽位 | “控制面已通过正式 contract 闭合” | 仍不能声明第二平台充分性，因为缺少真实第二平台 PoC |
| B. 当前平台 adapter closure | 不新增 `h_control_contract_t`；将 `h_rpc_slave_if.c` 物理迁出 core 或在 active source matrix 中降级为 ESP-IDF control adapter；`serial_ll_if.c` 保留内部 fops 对象模型，但其平台能力迁到 `h_*` wrapper，直接 transmit 优先改为 `h_transmit` | “当前 ESP-IDF 平台控制面 active path 已显式 adapter 化，不再依赖 legacy vtable” | 不能声明“控制面 contract 已闭合”，也不能把该路径当成第二平台移植充分性证据 |

本文件默认推荐路径 A，因为它给后续第二平台 PoC 留下更清晰的 port contract 边界。若为了快速完成当前平台收口选择路径 B，必须在最终实施结果中降低表述强度，并保留后续升级到路径 A 的退场条件。

## 6. 完成定义

本阶段完成时，允许使用以下表述：

> 当前 ESP-IDF 平台 active path 已完成解耦；core、控制面入口、当前 ESP-IDF transport driver 与 port adapter 均通过显式 contract / wrapper 运行。

如果 WP 1 选择 5.4 节路径 B，则允许表述需要降级为：

> 当前 ESP-IDF 平台 active path 已完成解耦；控制面通过显式 adapter 边界运行，尚未升级为独立 control contract。

本阶段完成后，仍不允许使用以下表述：

- “Host 通用框架已经 v1 完成”
- “新增平台只需实现 port contract 即可”
- “跨平台 contract 充分性已经被真实平台证明”
- “所有 legacy 文件已经删除”
- 选择路径 B 时，不允许说“控制面 contract 已闭合”

## 7. Work Packages

### WP -1：代码级前置补丁

目标：把 5.3 节列出的隐含假设变成代码事实。该 WP 不迁移 SDIO / UART driver 主体，只补齐后续迁移所需的最小 contract、wrapper、校验和边界。

- [ ] Step P.1：补齐 SDIO / UART wrapper 宏
  - `h_sdio_card_init`
  - `h_sdio_read_reg`
  - `h_sdio_write_reg`
  - `h_uart_flush`
  - 验收：新增 wrapper 均只转发到 `g_h_transport` 已有槽位，不引入新的 legacy 入口。

- [ ] Step P.2：固定 SDIO `card_deinit` 收口方式
  - 首选实现：在 `host/port/esp-idf/h_transport_sdio.c` 的 `h_sdio_deinit_adapter()` 内部调用 `hosted_sdio_card_deinit()`，再调用 `hosted_sdio_deinit()`。
  - 只有当 SDIO driver 仍必须在 transport deinit 前显式分阶段释放 card 资源时，才扩展 `h_transport_contract_t` 增加 `sdio_card_deinit`。
  - 无论采用哪种方式，都必须在 WP 2 文档结果中记录原因，避免后续误以为遗漏。

- [ ] Step P.3：补齐 `h_validate_contracts()` fail-fast 校验
  - SDIO：校验 `sdio_card_init`、`sdio_read_reg`、`sdio_write_reg`、`sdio_read_block`、`sdio_write_block`、`sdio_wait_intr`，以及 reset 所需 `gpio_config` / `gpio_write`。
  - UART：校验 `uart_read`、`uart_write`、`uart_flush`，以及 reset 所需 `gpio_config` / `gpio_write`。
  - 保持现有 common 校验：`init`、`deinit`、`bus_ready`、`transmit`。

- [ ] Step P.4：固定 thread lifecycle 迁移规则
  - 禁止把 `_h_thread_create(...)` 逐字替换为 `h_thread_create(...)`。
  - 旧返回值模式必须改成 out 参数模式。
  - 删除线程时只调用 `h_thread_delete(thread)` 并将变量置 NULL；不手动释放线程句柄。
  - 该规则写入 WP 2 / WP 3 的代码审查清单和 isolation 脚本说明。

- [ ] Step P.5：处理 `h_rpc_slave_if.c` 的 core 边界
  - 先按 WP 0 选择 5.4 节路径 A 或路径 B。
  - 路径 A：把当前 serial low-level / rpc platform 逻辑迁到 ESP-IDF control contract implementation，例如 `host/port/esp-idf/h_control_serial.c`；`host/core/src/h_serial_if.c` 只通过 `h_control_*` wrapper 调用控制面字节流能力。
  - 路径 B：不新增 `h_control_contract_t`，但必须把 `h_rpc_slave_if.c` 从 core active path 降级为 ESP-IDF control adapter；优先物理迁到 `host/port/esp-idf/`，或在 active source matrix 中明确标为 adapter 文件。
  - 两条路径都要求：普通 core 文件不直接 include `serial_ll_if.h`，不直接访问 `serial_ll_if_g->fops`。
  - 若路径 B 保留 `serial_ll_if.c` fops 对象模型，该 fops 只能是 adapter 内部细节；`serial_ll_if.c` 的 `g_h.funcs->_h_*` 必须迁到 `h_*` wrapper，直接 `esp_hosted_tx()` 优先迁到 `h_transmit()`，否则必须写入 allowlist 和退场条件。

### WP 1：控制面闭合

## 9. 风险与处理原则

### 风险 1：把当前平台完成误叫成 v1

处理：本文档完成后只能声明“ESP-IDF 当前平台 active path 完全解耦”，不能声明“跨平台 contract 充分性已证明”。

### 风险 2：SDIO / UART 改动过大影响稳定性

处理：按 transport 分支逐个迁移，每个 transport 独立编译验证，不与控制面改造混在同一提交里。

### 风险 3：控制面 contract 设计过早泛化

处理：WP 0 必须先选择路径 A 或路径 B。路径 A 只抽象当前实际需要的 open / close / read / write / ready，不预留复杂异步模型；路径 B 则必须降低表述强度，避免把 adapter closure 误写成 contract closure。

### 风险 4：allowlist 变成长期豁免

处理：每个 allowlist 项必须包含 owner、原因和退场条件；不能只写“temporary”。

### 风险 5：旧文件未删除导致误判

处理：不以文件是否存在作为完成标准，只以 active path 是否依赖作为完成标准。

### 风险 6：隐藏头文件依赖绕过 isolation

处理：`check_current_platform_isolation.sh` 必须检查 core include 和符号访问，不只检查 `g_h.funcs` / `->_h_`。`serial_ll_if.h`、`serial_ll_if_g->fops` 这类旧对象模型依赖不能留在 core。

### 风险 7：线程迁移引入句柄所有权错误

处理：SDIO / UART 迁移时禁止用文本替换处理 `_h_thread_create` / `_h_thread_cancel`。必须按 `h_thread_create(..., &thread)` 和 `h_thread_delete(thread)` 的新 contract 语义改写，并在 deinit 后置 NULL。

### 风险 8：轻量 adapter 路径被误当成长期架构结论

处理：如果 WP 1 选择路径 B，必须在实施结果中记录退场条件：后续第二平台 PoC 重启前，需要重新评估是否升级到路径 A。路径 B 只能证明当前 ESP-IDF active path 已显式化，不能证明控制面 contract 充分。
