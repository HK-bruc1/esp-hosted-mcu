# 25. 移植友好型最佳实践优化方案

> 基线日期：2026-06-09
> 前置状态：24 号文档执行后，当前 ESP-IDF host active source set 已完成 legacy port 退场，GitHub CI 已通过。
> 本文目标：把当前状态从“ESP-IDF active path 已解耦”继续推进到“移植入口清晰、公共表面少误导、port 选择机制成形”的最佳实践状态。

---

## 1. 当前结论

当前状态可以准确表述为：

> 当前 ESP-IDF 平台 host active source set 已完成 legacy port 退场与 contract/wrapper 化解耦；core、控制面、transport driver、ESP-IDF port adapter 均已脱离 `g_h.funcs` 主路径，并通过 Linux mock、core isolation、四 transport current-platform isolation 和 ESP-IDF host build matrix 验证。

但还不能表述为：

> Host 通用框架 v1 已完成。
> 任意第二平台可以零摩擦接入。
> 全仓 legacy 头文件和旧兼容 API 已经清零。

剩余问题不是运行路径问题，而是移植体验和 API 表面问题。

## 2. 代码事实基线

### 2.1 已完成事实

| 检查项 | 当前事实 |
|---|---|
| `host/port/esp/freertos/src/*.c` | 不再进入 ESP-IDF host active source set |
| `host/port/esp/freertos/include` | 不再进入 ESP-IDF host include path |
| `g_h.funcs` / `->_h_` / `HOSTED_FREE` 等旧 vtable 调用 | current-platform isolation strict 检查为 0 |
| `esp_hosted_tx()` | 已通过 `transport_drv_api.h` 显式化为 transport leaf driver internal API |
| core portable boundary | `scripts/check_core_isolation.sh` 通过，12/12 |
| 四 transport active path | `scripts/check_current_platform_isolation.sh spi|spi_hd|sdio|uart --strict` 全部通过 |

### 2.2 剩余缺口

#### 缺口 A：旧 OS abstraction 头仍在 active/public 表面可见

当前仍有以下非 legacy 文件 include `esp_hosted_os_abstraction.h`：

| 文件 | 当前性质 | 风险 |
|---|---|---|
| `host/esp_hosted.h` | 公共 umbrella API 头 | 新平台使用者 include 主入口时会被暴露到旧 vtable 类型 |
| `host/drivers/transport/transport_util.h` | active transport helper header | 传递旧头到 transport driver |
| `host/core/src/h_transport_util.c` | active compiled source | core 文件仍显式 include 旧头，虽然不再调用旧 vtable |
| `host/api/src/esp_hosted_ota_api.c` | active compiled source | 仅需 `h_msleep()`，不应 include 旧头 |
| `host/drivers/bt/vhci_drv.c` | conditional-active source | 仅需 alignment / weak / wrapper 能力，不应 include 旧头 |
| `host/port/esp-idf/tools/stats.c` | active ESP-IDF tool source | 已改走 `h_*`，旧头 include 可移除 |
| `host/drivers/transport/transport_util.c` | legacy / non-active duplicate source | 不参与当前 CMake，但仍造成全仓审计噪音 |

注意：这些 include 当前不等价于 `g_h.funcs` 运行时依赖。它们是头文件表面和迁移体验债务。

#### 缺口 B：CMake 仍硬编码 ESP-IDF port

根 `CMakeLists.txt` 直接加入：

```cmake
${host_dir}/port/esp-idf/port_init.c
${host_dir}/port/esp-idf/h_osal.c
${host_dir}/port/esp-idf/h_event.c
...
```

这对当前 ESP-IDF 平台是正确的，但对第二平台移植者不够友好。未来新增 Zephyr / RTOS-X 时，需要改根 CMake，而不是只新增一个 port 目录。

## 3. 目标与非目标

### 3.1 目标

1. 当前 active source 和主公共入口不再 include `esp_hosted_os_abstraction.h`。
2. `esp_hosted_os_abstraction.h` 降级为 legacy compatibility header，不再作为新 port 的参考入口。
3. 根 `CMakeLists.txt` 引入 host port selector 的结构骨架，当前默认仍为 `esp-idf`。
4. ESP-IDF build、Linux mock、current-platform isolation 结果不回退。
5. 补充移植者视角的最小说明：新平台优先实现 `h_port_contract.h` 三合约，而不是旧 `hosted_osi_funcs_t`。

### 3.2 非目标

1. 不启动第二平台 PoC。
2. 不删除所有 legacy 死代码。
3. 不改变 wire protocol。
4. 不改 public Wi-Fi / BT / OTA API 行为。
5. 不把 `esp_hosted_tx()` 升级为 public port contract；它仍是 transport leaf driver internal API。
6. 不在本阶段承诺 Zephyr CMake 可直接构建，只建立 port selector 的工程入口。

## 4. 架构决策

### 4.1 `esp_hosted_os_abstraction.h` 的最终定位

该头文件不再作为新架构 port contract。它应被定位为：

> Legacy compatibility header，仅服务旧外部代码或未迁移死代码；新 active path 和新 port 模板不得依赖它。

处理原则：

| 场景 | 处理 |
|---|---|
| `host/esp_hosted.h` transitive include | 移除 |
| active `.c` / `.h` include | 替换为 `h_wrapper.h`、`h_types.h`、`mempool.h`、`h_port_config.h` 等精确头 |
| 直接 include `esp_hosted_os_abstraction.h` 的外部用户 | 暂不破坏，保留该头并标注 deprecated |
| legacy 死代码 include | 可保留，但必须不进入 active audit scope |

### 4.2 类型与宏替代规则

| 旧来源 | 新来源 |
|---|---|
| `hosted_mem_cap_t` / `HOSTED_MEM_CAP_*` | `common/mempool/include/mempool.h` |
| `HOSTED_MEM_ALIGNMENT_*` | `H_MEM_ALIGNMENT_*` from `h_types.h`，或 `h_wrapper.h` 的兼容 fallback |
| `_h_malloc_align` / `_h_free_align` | `h_malloc_align()` / `h_free_align()` |
| `_h_msleep` | `h_msleep()` |
| `H_WEAK_REF` | `h_port_config.h` |
| `esp_event_base_t` in old vtable | 不进入新 active source；event 走 `h_event_*` wrapper |

### 4.3 Port selector 形态

推荐采用 CMake 级 port selector，而不是把所有 port 文件继续硬编码在根 `CMakeLists.txt`。

建议变量：

```cmake
set(ESP_HOSTED_HOST_PORT "esp-idf" CACHE STRING "ESP-Hosted host port implementation")
```

建议目录结构：

```text
host/port/
├── include/                 # port contract, wrapper, generic dispatch headers
├── esp-idf/
│   ├── port.cmake            # exports ESP_HOSTED_PORT_SRCS / includes / requires
│   ├── port_init.c
│   ├── h_osal.c
│   ├── h_event.c
│   └── h_transport_*.c
├── linux/                    # Linux mock, existing test port
└── template/                 # optional future skeleton, documentation only
```

根 CMake 只负责 common/core/api/driver source set 与 selected port 的拼接：

```cmake
set(ESP_HOSTED_HOST_PORT "esp-idf" CACHE STRING "ESP-Hosted host port")
include("${host_dir}/port/${ESP_HOSTED_HOST_PORT}/port.cmake")

list(APPEND srcs ${ESP_HOSTED_PORT_SRCS})
list(APPEND priv_include ${ESP_HOSTED_PORT_PRIV_INCLUDE_DIRS})
list(APPEND driver_requires ${ESP_HOSTED_PORT_REQUIRES})
list(APPEND driver_priv_requires ${ESP_HOSTED_PORT_PRIV_REQUIRES})
```

当前阶段只要求 `esp-idf` selector 行为等价，不要求 Linux mock 改走 ESP-IDF component CMake。

## 7. 执行顺序

推荐顺序：

```text
WP 0
  ↓
WP 1 → WP 2 → WP 3
  ↓
WP 4
  ↓
WP 5
  ↓
WP 6
```

理由：

1. 先清旧头 include，减少后续 port selector 改造时的变量。
2. 再改公共 umbrella，避免对外 API 表面继续传播旧 vtable。
3. 再处理 dead duplicate source，降低审计噪音。
4. 最后抽 CMake port selector，因为这是构建结构变化，应该在源文件边界稳定后做。

## 8. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 外部用户直接依赖 `esp_hosted.h` 间接拿到旧 OS abstraction 类型 | 移除 include 后可能暴露外部代码隐式依赖 | 保留 `esp_hosted_os_abstraction.h` 文件本身；只移除 umbrella 传递 include |
| `transport_util.h` include 调整导致 transport driver 编译顺序问题 | SPI/SDIO/UART/SPI-HD 编译失败 | 每个 transport 独立 build；必要时补精确 include |
| `port.cmake` 拆分导致 IDF component requirements 遗漏 | CI host build fail | 保持 `PRIV_REQUIRES` 初期全量搬迁，不急于最小化依赖 |
| grep 误报 legacy 死代码 | 验收争议 | check 脚本必须显式定义 active/public scope，不做全仓绝对清零 |
| 过度设计 port selector | 本轮变更变大 | 只做默认 `esp-idf` selector，不做 Zephyr 实现 |

## 9. 完成后的允许表述

允许：

> 当前 ESP-IDF 平台 host active path 已完成 legacy port 退场；公共 API 表面不再传递旧 OS abstraction 头；ESP-IDF port 通过 port selector 接入，新增平台的工程入口已明确为实现 `h_port_contract.h` 三合约和对应 `port.cmake`。

禁止：

> Host 通用框架 v1 已完成。
> 第二平台 PoC 不再需要。
> 所有 legacy 代码已经删除。
> 新平台无需任何构建系统适配即可直接接入。
