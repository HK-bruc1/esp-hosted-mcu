# 23. ESP32平台完全解耦与移植友好型收尾方案

> 本文档承接 22 号文档的执行结果。
>
> 22 号文档已经完成 core、控制面 Path B、四类 transport leaf driver 的主链路收口。
> 本文档只处理 22 号之后复核发现的 ESP32 / ESP-IDF 平台剩余缺口：
> **从“Wi-Fi 主链路移植友好”推进到“当前 ESP32 平台 active source set 可声明完全解耦”**。

---

## 1. 当前结论

截至 2026-06-05 的代码复核结论：

| 维度 | 当前状态 | 结论 |
|---|---|---|
| core 层 | `host/core/src/` 12/12 隔离，未发现直接 `g_h.funcs` / `->_h_` / `transport_pserial_*` | 已达标 |
| 控制面 | Path B adapter closure；`h_rpc_slave_if.c` 已迁出 core；`serial_ll_if.c` 的 legacy OSAL 调用已清零 | 当前平台达标，尚非独立 control contract |
| transport leaf driver | SPI / SPI-HD / SDIO / UART 直接 legacy 调用已清零 | 已达标 |
| API / tools | `esp_hosted_api.c` 存在 1 处 `#if 0` 死代码 legacy 调用；`stats.c` 通过 `H_DEFLT_FREE_FUNC` 间接依赖旧 vtable | 未完全达标 |
| power save | `power_save_drv.c` 仍大量直接使用 `g_h.funcs->_h_*`，且新 contract 缺少 power-save 专属能力 | 未达标 |
| BT VHCI | `vhci_drv.c` 在 BT VHCI 配置下仍直接使用 `g_h.funcs`，并通过 `H_DEFLT_FREE_FUNC` 间接依赖旧 vtable | 未达标 |
| legacy ESP/Freertos port | 仍在 CMake active source set，仍定义 `g_h` 并保留 `HOSTED_*` / `g_h.funcs` 路径 | 允许作为临时 adapter，不能作为最终完全解耦状态 |
| 编译验证 | 已新增 `examples/host_compile_check/`，但仍需在 ESP-IDF 环境中实际跑四 transport build matrix | 待验证 |

当前允许声明：

> ESP-IDF 当前平台 core、控制面 Path B、Wi-Fi transport 主链路和四类 leaf driver 已完成静态解耦，具备主链路移植友好基础。

当前不允许声明：

> ESP32 / ESP-IDF host active source set 已完全解耦。

---

## 2. 本文档目标

本文档的目标是关闭剩余的 current-platform gap，使最终可以声明：

> 当前 ESP32 / ESP-IDF host active source set 中，除明确的 ESP-IDF port adapter 边界外，不再直接依赖 legacy `g_h.funcs` vtable、`HOSTED_*` legacy macro、`H_DEFLT_FREE_FUNC` 宏链或未声明的旧 transport 入口。新平台移植时，主链路和可选功能都能通过明确 contract / wrapper / compile gate 处理。

本文档不做以下事情：

1. 不启动第二平台真实 PoC。
2. 不宣称 Host 通用框架 v1 完成。
3. 不改 wire protocol、RPC ID、protobuf schema 或 slave 行为。
4. 不要求一次性删除所有历史文件；但 active source set 中的 legacy 依赖必须么迁移、要么 compile-gate、要么被标为临时 adapter 并有退场条件。

---

## 3. 完成强度分级

为了避免“完全解耦”口径混乱，后续评估按以下分级执行：

| 等级 | 名称 | 完成定义 | 当前状态 |
|---|---|---|---|
| L0 | Core closure | `host/core/src/` 无 ESP-IDF / FreeRTOS / legacy vtable / legacy pserial 直接依赖 | 已完成 |
| L1 | Wi-Fi 主链路 closure | core、控制面 Path B、SPI/SPI-HD/SDIO/UART leaf driver、`h_transport_drv.c` 均走 `h_*` / contract | 基本完成 |
| L2 | ESP32 active source closure | CMake active source set 中 API、tools、power-save、BT 条件路径、legacy port adapter 的 legacy 依赖均迁移或显式 gate | 未完成，本文档目标 |
| L3 | 移植友好型 closure | 新平台可仅实现明确 contract / wrapper / feature gate，不需要复刻 `g_h.funcs` 旧 vtable 才能编译主链路 | 未完成，本文档目标的下限 |
| L4 | 跨平台充分性证明 | 第二平台真实硬件 PoC 通过 | 非本文档目标 |

本文档完成后，目标至少达到 L2，并具备 L3 的代码结构基础。

## 4. 当前剩余缺口清单

### 4.1 API 层死代码 legacy 调用

文件：

- `host/api/src/esp_hosted_api.c`

当前问题：

- `#if 0` 内仍有 `g_h.funcs->_h_create_semaphore(1)`。
- 虽然不是编译路径，但会污染静态检查结果，并降低“grep 清零”可信度。

处理原则：

- 删除该 `#if 0` 死代码，或完整改成 `h_sem_create()` / `h_sem_take()` / `h_sem_give()`。
- 不允许长期把 active API 文件放入 `g_h.funcs` allowlist。

### 4.2 `stats.c` 的间接 legacy 宏链

文件：

- `host/port/esp-idf/tools/stats.c`
- `host/drivers/transport/transport_drv.h`

当前问题：

- `stats.c` 已迁移大多数 OSAL 调用，但 raw throughput 路径仍直接调用 `esp_hosted_tx()`。
- 其中一处 free callback 使用 `H_DEFLT_FREE_FUNC`。
- `H_DEFLT_FREE_FUNC` 定义为 `g_h.funcs->_h_free`，属于宏链隐藏的 legacy vtable 依赖。

处理原则：

- `stats.c` 中 `esp_hosted_tx()` 改为 `h_transmit()`。
- `H_DEFLT_FREE_FUNC` 改为 `h_free_fn`。
- `stats.c` 不再 include `transport_drv.h` 或 `port_esp_hosted_host_os.h`，除非该文件被明确降级为 ESP-IDF-only diagnostic adapter 且在脚本 allowlist 中记录 owner、原因、退场条件。
- `h_free_fn` 已在 `host/port/include/h_wrapper.h` 中存在，可直接使用；不需要新增 wrapper。
- `H_BUFF_ZEROCOPY` / `H_BUFF_NO_ZEROCOPY` 当前同时存在于旧 `transport_drv.h` 和新 `h_transport_drv.h`。移除旧头文件前，必须确认 `stats.c` 从新公共头或 wrapper 可见这些常量，不能为了去旧头而复制私有宏。

### 4.3 BT VHCI 条件 active path

文件：

- `host/drivers/bt/vhci_drv.c`

触发条件：

- `CONFIG_ESP_HOSTED_NIMBLE_HCI_VHCI`
- `CONFIG_ESP_HOSTED_BLUEDROID_HCI_VHCI`

当前问题：

- `g_h.funcs->_h_malloc_align`
- `g_h.funcs->_h_free_align`
- `esp_hosted_tx()`
- `H_DEFLT_FREE_FUNC`
- include `transport_drv.h`
- include `port_esp_hosted_host_os.h`

处理原则：

- 内存替换为 `h_malloc_align()` / `h_free_align()`。
- transmit 替换为 `h_transmit()`。
- free callback 替换为 `h_free_fn`。
- 移除旧头文件依赖。
- 移除 `transport_drv.h` 后，`H_BUFF_NO_ZEROCOPY` / `H_BUFF_ZEROCOPY` 必须来自新公共头，优先使用 `host/core/include/h_internal/h_transport_drv.h` 或后续抽出的 transport common header。
- 如果本阶段不覆盖 BT，则 CMake 必须使 BT VHCI 不进入默认 current-platform closure，并在文档中声明 BT VHCI 为未完成可选功能；不能同时宣称“全平台 active source set 完全解耦”。

推荐路线：

> 迁移 BT VHCI，不建议排除。它的替换量小，且直接影响“全功能 host 是否移植友好”的表述强度。

### 4.4 Power-save 专属能力缺口

文件：

- `host/drivers/power_save/power_save_drv.c`
- `host/port/include/h_port_contract.h`
- `host/port/include/h_wrapper.h`
- `host/port/esp-idf/h_osal.c`
- 可能涉及 `host/port/esp-idf/h_transport_*.c`

当前问题：

`power_save_drv.c` 仍直接依赖以下旧能力：

| Legacy 能力 | 当前用途 | 新 contract 状态 |
|---|---|---|
| `_h_get_time_ms` | wakeup debounce / timer | OSAL 已有 `get_time_ms` |
| `_h_config_gpio` | power-save init 时配置 wakeup GPIO 输入模式 | transport contract 已有 `gpio_config` |
| `_h_read_gpio` / `_h_write_gpio` / `_h_config_gpio_as_interrupt` / `_h_teardown_gpio_interrupt` | host wakeup GPIO | transport contract 已有近似 GPIO 能力 |
| `_h_restart_host` | wakeup 异常恢复 | OSAL optional 已有 |
| `_h_msleep` | stabilization delay | OSAL 已有 |
| `_h_timer_start` / `_h_timer_stop` | power-save timer | OSAL contract 已有，但 ESP-IDF `h_osal.c` 当前为 stub，必须先补真实 adapter |
| `_h_get_host_wakeup_or_reboot_reason` | 判断是否从 power save 唤醒 | 缺少 |
| `_h_hold_gpio` | deep sleep 前保持 reset GPIO | 缺少 |
| `_h_pull_gpio` | sleep GPIO 上下拉配置 | 缺少 |
| `_h_config_host_power_save_hal_impl` | ESP-IDF power-save HAL 配置 | 缺少 |
| `_h_start_host_power_save_hal_impl` | 启动 ESP-IDF power-save HAL | 缺少 |

处理路线 A（推荐）：

- 先把 `host/port/esp-idf/h_osal.c` 中的 `h_timer_create` / `h_timer_start` / `h_timer_stop` / `h_timer_delete` 从 stub 改为真实 `esp_timer` adapter。
- GPIO 缺口固定放入 `h_transport_contract_t`，只补 `gpio_pull` / `gpio_hold`，不新建 `h_gpio_contract_t`。
- Power-save HAL 缺口固定放入 `h_osal_contract_t` optional extension，补 `get_host_wakeup_or_reboot_reason`、`config_host_power_save_hal`、`start_host_power_save_hal`。
- 本轮不新建 `h_power_contract_t`。当前缺口只有 5 个新增槽位，引入新 contract 会增加初始化、校验和文档复杂度，不划算。
- `power_save_drv.c` 只通过 `h_*` wrapper 调用这些能力。
- ESP-IDF 具体实现放在 `host/port/esp-idf/`。

处理路线 B（可接受但表述较弱）：

- 明确将 power-save 从本轮 full closure 中 compile-gate 掉。
- 默认 ESP32 host compile check 不启用 power-save。
- 文档只能声明“Wi-Fi 主链路 active source set 解耦”，不能声明“ESP32 平台全功能 active source set 完全解耦”。
- 注意：`power_save_drv.c` 当前在 `CMakeLists.txt` 中无条件编译。选择路线 B 时必须同步增加 Kconfig / CMake guard，否则“compile-gate”只是文档表述，不是工程事实。

推荐路线：

> 选择路线 A。Power-save 当前在 CMake 中无条件编译，且 `h_osal.c` 已经把 `ps_init` / `woke_from_ps` 挂到 OSAL optional extension，继续留下旧 vtable 会破坏 current-platform full closure。

### 4.5 Legacy ESP/Freertos port adapter 退场

文件：

- `host/port/esp/freertos/src/port_esp_hosted_host_os.c`
- `host/port/esp/freertos/src/port_esp_hosted_host_sdio.c`
- `host/port/esp/freertos/src/port_esp_hosted_host_spi.c`
- `host/port/esp/freertos/src/port_esp_hosted_host_spi_hd.c`
- `host/port/esp/freertos/src/port_esp_hosted_host_uart.c`
- `host/port/esp/freertos/src/port_esp_hosted_host_transport_defaults.c`

当前问题：

- CMake 仍编译这些文件。
- `port_esp_hosted_host_os.c` 定义 `struct hosted_config_t g_h = HOSTED_CONFIG_INIT_DEFAULT();`。
- per-transport legacy port 文件仍使用 `g_h.funcs` / `HOSTED_*`。
- 新 `host/port/esp-idf/h_transport_*.c` adapter 仍调用旧 `hosted_*` 实现。

处理原则：

- 短期可以保留旧 `hosted_*` 实现作为 ESP-IDF native helper。
- 但 active helper 内部不能再依赖 `g_h.funcs`。
- `g_h` 旧 vtable 只能在未编译的 legacy compatibility 文件中存在，不能作为当前 active source set 的必要依赖。

推荐收口方式：

1. 将旧 per-transport port 文件中内部 OSAL 调用改成 native ESP-IDF API 或局部 helper，避免通过 `g_h.funcs` 绕回旧 vtable。
2. 将 `H_DEFLT_FREE_FUNC` 退场，统一使用 `h_free_fn`。
3. 当没有 active 文件依赖 `g_h` 后，从 CMake active source set 移除 `port_esp_hosted_host_os.c`，或将其改为仅提供 native helper 而不定义 `g_h`。
